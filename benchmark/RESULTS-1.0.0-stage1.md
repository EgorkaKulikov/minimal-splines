`DenseMatrix`/LAPACK numerical-core 1.0.0 и смены критерия вырожденности на оценку числа
обусловленности (`MinimalSplineBasis.MAX_CONDITION = 1e8`). Методика и машина — как в
`BASELINE-0.1.0.md`: Apple M1 Pro (8 процессоров), Corretto 21.0.10, netlib JNILAPACK (Accelerate);
сетка `Grid.uniform(n, 0, 1)`, медиана из 5 после 3 прогревов, мс.

## Оценка

1. Построение базиса замедлилось в 3–5 раз при n = 10² и в ~13 раз при n = 10³: на каждый из n
   интервалов приходится два вызова LAPACK через JNI (dgecon после LU-факторизации и dgetri),
   то есть накладные расходы вызова доминируют над арифметикой 3×3. Стоимость линейна по n —
   около 3 мкс на интервал (3.5 мс при n = 10³, 5.8 мс при n = 2·10³); экстраполяция на n = 10⁴
   даёт ≈ 30 мс, что много меньше порога 2 с. Оптимизация построения (батч либо собственные 3×3
   в локальных координатах) по производительности не обязательна; решение на этапе 1d
   определяется обусловленностью, а не временем.
2. Семейства функционалов (theta, xi1, mu) и вычисление сплайна в пределах шума
   (отношение 0.8–1.6, единичный выброс xi1/H/1000 — 2.4 при абсолютных 0.38 мс).
3. Существенный результат для этапа 1d: в глобальных координатах порождающей системы
   cond(M_k) на [0,1] растёт как n² (≈ 3·10⁴ при n = 10², ≈ 3·10⁶ при n = 10³, ≈ 3·10⁸ при n = 10⁴
   для B; для H — в 4 раза больше), поэтому критерий cond ≤ 10⁸ отвергает базис начиная с
   n ≈ 2·10³ (H) и n ≈ 3·10³ (B). В 0.1.0 порог det/scale отвергал сетки с n ≥ 5·10³.
   Переход к локальным координатам (этап 1d) должен снять зависимость cond от n; до этого
   рабочий диапазон размеров сетки на [0,1] — n ≤ 2·10³ (B) и n ≤ 10³ (H).
