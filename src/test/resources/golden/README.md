# Эталоны поведения библиотеки (golden)

Файлы `*.json` фиксируют численное поведение `minimal-splines` версии 0.1.0 и служат
для контроля регрессии при переработке: `grid.json` (узлы и признаки сеток),
`basis.json` (базис и сплайн на контрольных точках), `functionals.json` (семейства
аппроксимирующих функционалов), `metrics.json` (`errorEh`),
`algebra.json` (`nonDegenerate`, порождающие системы).

Формат: JSON без внешних зависимостей; каждое число `Double` записано как 16 шестнадцатеричных
цифр raw bits (`Double.toRawBits`), что исключает потери при печати и разборе. Поле
`generatedWith` содержит версию библиотеки, имя реализации BLAS/LAPACK и дату формирования.

Формирование заново: `./gradlew regenerateGolden` (задача исключена из `test`, `fastTest` и Kover).

Допуски проверки (`Golden*Test`, тег `fast`): побитовое совпадение — для целочисленной и
комбинаторной логики (`interval`, `isCoincident`, `nonDegenerate`, флаги семейств) и явных
формул (`Grid`, алгебра 3-векторов, `phi`, `wronskian` систем без трансцендентных функций); относительное
`max|got - exp| / max(max|exp|, 1) <= 1e-10` — для величин, проходящих через решение малых СЛАУ
(`omega*`, `evalSpline*`, коэффициенты проекторов, `cChi`, `errorEh`), где допустимо
расхождение в порядке операций реализации BLAS/LAPACK и способа обращения 3x3 матриц.

Решение 1c: для `basis`, `functionals` и `errorEh` относительный допуск равен `1e-10`
(`GoldenCompare.BASIS_TOLERANCE`). Эталоны 0.1.0 получены обращением M_k по формулам Крамера в
глобальных координатах порождающей системы при числах обусловленности до ~10⁴; погрешность такого
пути — порядка cond·ε ≈ 10⁻¹²…10⁻¹¹, что и наблюдается при сравнении с LAPACK (макс. 1.05·10⁻¹¹).
Допуск 10⁻¹⁰ покрывает погрешность эталона с десятикратным запасом и на порядки меньше любой
погрешности метода. Для `grid` сравнение побитовое.

Величины, вычисляемые через `Math.sin`, `Math.cos`, `Math.pow` (порождающая система T, сетки
`quasiUniform` и `geometric`), сравниваются с относительным допуском
`GoldenCompare.TRANSCENDENTAL_TOLERANCE = 16 ulp(1) ≈ 3.6e-15`, а не побитово: HotSpot использует
платформенные интринсики этих функций, результаты которых на x86_64 и aarch64 различаются в младшем
бите (эталоны сняты на macOS aarch64, CI выполняется и на ubuntu x86_64). В `geometric` расхождение
в один ulp у q = R^{1/(n-1)} переносится на q^j с множителем j ≤ n и складывается с расхождениями
отдельных степеней — до ~7 ulp(1) при n = 32; допуск в 16 ulp(1) покрывает это с запасом и остаётся
на порядки меньше любого расхождения алгоритма.
